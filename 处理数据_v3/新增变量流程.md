# 新增一个要计算的变量：流程

更新：2026-10-21。适用于 v3 管线（网页“数据管理”和命令行 `process_data.py` 共用）。

## 一句话

**直接告诉 AI，按下面的模板写清楚；AI 按固定的 6 步做完，你只需要做两件事：双击测试脚本、确认是否开始处理数据。**

## 先看是否“不用写代码”

很多变量用命名规则就能自动得到，在网页“可处理变量”里搜一下就知道：

| 写法 | 意思 | 例子 |
|---|---|---|
| `X_polar` | X 以海平面气压中心 `slp_center` 为原点插值到 方位角 × 半径 | `rh_polar` |
| `X1_polar` | X 以**当前高度**的气压中心 `layer_center` 为原点（`1` 不是第 1 层） | `rh1_polar` |
| `X_asy_polar` | 每个半径减去方位平均，只留非对称部分 | `wa_asy_polar` |
| `X_asy1w_polar`、`X_asy2w_polar` … | 第 1、2 … 波分量 | `vt_asy1w_polar` |

只要 X 已经登记，这些名字都可以直接在网页上处理，不需要改代码。

## 需要新写算法时：告诉 AI 这些信息（复制模板填写）

```
新变量：<英文名，只用字母、数字、下划线，如 vort_rel>
物理含义：<一句话，如 相对涡度>
公式 / 算法：<如 ζ = ∂v/∂x − ∂u/∂y；或“按 某某 2019 第 5 页 式(3)”>
输入变量：<如 ua、va；需要中心的写明 slp_center 还是 layer_center>
维度：<三维（随高度） / 二维地面 / 每个时次一个数（标量） / 随高度的标量>
单位：<如 s-1>
固定参数：<如 积分半径 0–200 km、固定高度 1 km 与 6 km、用 d02 环境场；没有就写“无”>
参考文献：<可选，库里的 PDF 名称和页码>
打算怎么用：<如 想画 0–100 km 的时间–高度剖面，比较 315 land 与 sea>
```

信息不全也可以先说，AI 会先查文献库和现有变量，再问你缺的部分。

## AI 的固定 6 步

1. **查重与定口径**：在 `VARIABLES_REFERENCE.md` 和注册表里查有没有同义变量；需要时查文献库核对公式（引用写 PDF 页码）。口径有歧义时先问你。
2. **写算法**：新建 `wrf_processing_v3/variables/<变量名>.py`，里面一个 `process(ctx)`：用 `ctx.read("ua")` 读依赖，算完用 `save(ctx, 数组, units=..., derived_from=[...])` 保存（参考 `wind_speed_10.py`、`vt1.py`）。
3. **登记**：在 `wrf_processing_v3/_scientific_registry.py` 加一行，例如
   `derived("vort_rel", "s-1", ["ua", "va"])`（第 4 个参数是维度：默认 `"height"`，地面 `"surface"`，标量 `"scalar"`）。需要固定高度、跨 domain 依赖的，在 `build_registry()` 里用 `Dependency(name, height=..., domain=...)` 写明。暖心类变量还要同步“处理高度”规则（见「顾问工作约定」）。
4. **写测试**：在 `处理数据_v3/tests/` 新增 `test_<变量名>.py`，用一个小的人造场核对数值（例如已知解析解），并检查登记的单位、维度和依赖。
5. **写说明**：在 `VARIABLES_REFERENCE.md` 对应表格加一行（单位、依赖、物理含义、计算方式）。**网页“可处理变量”鼠标悬停的说明就读这一行**，不写就只显示单位和依赖。
6. **测试并重启网页**：AI 写好测试脚本，你在 Mac 上双击（用 `wrf-webvis` 环境跑全部测试，通过才重启网页）。之后新变量出现在“可处理变量”里。

然后由你决定是否处理：在网页上选试验、时次、高度 → “预览依赖计划”看要算多少切片 → “提交处理”。AI 不会在没有你同意时从 wrfout 重新处理数据。

## 处理套餐（2026-11-02）

想把一批变量按固定时间步长、高度一键处理：只改 `processing_presets.json`（新增一组或改组里的变量），刷新网页即可在“数据管理 → 处理套餐”里用；不需要改代码。变量须已登记。

## 改已有变量的算法（不是新增）

- 改动会让旧结果和新算法不一致：在 `VariableSpec` 的 `options` 里提高 `algorithm_version`（或单独给这个变量指定版本），再对该变量勾选“重新计算选中的目标切片”或用 `--force-variable`。
- 旧版结果默认不删除；需要删除时先列清单，由你决定。

## 新增定中心方法 / 中心方案（2026-11-02）

不同的定中心方法不新增变量名，而是新增“中心方案”。依赖中心的变量（vt1_polar、tilt、rmw……）会在该方案下自动重算并单独存放，与中心无关的变量各方案共用。

- **同一算法换参数**：只在 `center_schemes.json` 新增一个方案。写一个新编号（小写字母、数字、下划线），给出 `label`、`description` 和按 domain 的 `center_options_by_domain`。可用参数见 `wrf_processing_v3/variables/_center_options.py`。
- **新算法**：
  1. 在 `wrf_processing_v3/_center_algorithm.py` 写定位函数。输入二维场（地面中心用 SLP，层中心用该高度的气压）和格距，返回浮点 y、x，以及要写进元数据的附加信息。
  2. 在 `_center_options.py` 的 `CENTER_ALGORITHMS` 登记：名称、参数及默认值、是否支持层中心（`supports_layer`）、是否支持首猜（逐层连续模式需要）。
  3. 新增一个方案选用它：地面中心写 `algorithm`，层中心写 `layer_algorithm`。
  4. 写测试：在合成涡旋上能找到中心，并且登记表调用与直接调用结果一致。
- 中心照旧按整数格点 `[y, x]` 保存（极坐标插值以它为原点），浮点中心写在元数据里。
- 已有数据的方案不要改参数，也不要改已登记算法的含义；要改就起新名字。
- 处理时在网页选方案，或用命令行 `--center-scheme <编号>`。实际计算前仍要先预览计划，并经你同意。
